## Module Name & Go Module

The Go module is `hinay.cn/admin` (not the directory name `hinay-admin`). All internal imports use this prefix, e.g. `hinay.cn/admin/internal/dao`. The module is defined in `server/go.mod` with `go 1.26`.

## Architecture: Request Lifecycle

Every API request flows through this middleware chain (`server/internal/cmd/cmd.go:36-51`):

```
CORS → RequestId → MiddlewareHandlerResponse → Auth → Casbin → OperationLog → Controller
```

Key behaviors enforced by these middlewares:
- **CORS**: Allows all origins (`*`), methods `GET,POST,PUT,DELETE,OPTIONS,PATCH`.
- **RequestId**: Reads `X-Request-Id` header or generates a GUID; writes it to response headers and ctx.
- **MiddlewareHandlerResponse**: GoFrame built-in — unwraps controller return values into `{code, message, data}` JSON.
- **Auth**: Parses JWT from `Authorization: Bearer <token>`, checks Redis blacklist (logout tokens), writes `LoginUser` to ctx. Only `/api/v1/auth/login` is in `publicPaths` (unauthenticated).
- **Casbin**: Enforces `(username, path, method)` via `g(r.sub, p.sub)` matcher. Super admin (`admin` role) always allowed. Session endpoints (`/auth/menus`, `/auth/userInfo`, `/auth/logout`, etc.) are on `authWhitelist` — any authenticated user passes, no RBAC check. This prevents users with no roles from being locked out after login.
- **OperationLog**: After `r.Middleware.Next()`, fires an async goroutine with `context.Background()` to insert audit log for POST/PUT/DELETE. Skips multipart uploads and 4xx responses.

## Context & User Extraction (`server/utility/contextx/`)

The codebase uses a **dual-write** pattern for context: both `ghttp.Request.SetCtxVar()` and standard `context.WithValue()`. This matters because logic-layer code may be called from background goroutines that don't have access to the original `*ghttp.Request`. Always use `contextx.LoginUser(ctx)` to extract the current user — it tries `context.Value` first, falls back to the request-level var.

```go
user := contextx.LoginUser(ctx)     // returns *model.LoginUser or nil
uid  := contextx.UserId(ctx)        // shorthand
token := contextx.JwtToken(ctx)     // current JWT string
isAdmin := contextx.IsAdmin(ctx)    // checks if user has "admin" role via Casbin g-policy
```

## Service / Logic Registration Pattern

The service layer uses manual DI with `init()` registration:

1. `server/internal/service/<module>.go` — defines interface `IXxx`, package-level singleton `localXxx`, getter `Xxx()`, and `RegisterXxx(i IXxx)`.
2. `server/internal/logic/<module>/<module>.go` — implements the interface as `sXxx struct{}`, registers via `init() { service.RegisterXxx(NewXxx()) }`.

Controllers are thin: each method is a single line `return service.Xxx().Method(ctx, req)`. Controllers are auto-generated by `gf gen ctrl`; when adding a new API, re-run the generator rather than hand-editing controller files.

## Database Access Rules

- **Never** use `g.DB().Model("xxx")` with hardcoded table names. Always use `dao.Xxx.Ctx(ctx)`.
- DAO and model/entity files under `server/internal/dao/` and `server/internal/model/{entity,do}/` are generated by `gf gen dao` and must not be hand-edited.
- Custom query logic goes in the logic layer, using the DAO as the entry point.
- All core tables include `deleted_at` for soft deletion (GoFrame handles this automatically via DAO).

## Casbin Enforcement Details

The Casbin model uses `g(r.sub, p.sub)` — the `sub` passed to `Enforce()` is the **username string**, not a role. The g-policy (`g, username, roleCode`) maps users to roles internally. Policy types:
- `p, roleCode, menu:<id>, *` — menu/button permission
- `p, roleCode, /api/path, METHOD` — API-level permission
- `g, username, roleCode` — user-role assignment

Policy changes (add/remove role permissions) call `casbinx.Reload(ctx)` to rebuild the in-memory enforcer from the `casbin_rule` table. The enforcer uses a custom `memAdapter` that reads from DB — it's not a file-based adapter.

## Frontend Token Refresh Queue

`web_src/app/composables/useRequest.ts` implements a sophisticated concurrent-request-safe 401 handler: when a 401 is received on any request (except `/auth/refresh` itself), the first failing request triggers a token refresh; all subsequent 401s that arrive during that refresh are queued. Once refresh completes, all queued requests retry with the new token. If refresh fails, the queue is drained and the user is redirected to `/login`.

The `useUserStore` persists token to `localStorage` (keys: `hinay_token`, `hinay_token_expire`) and restores on `restore()`.

## Frontend Permission Guard

`v-permission` directive (`web_src/app/plugins/permission.ts`) removes DOM elements when the user lacks a permission code. It waits until `menusLoaded` is true before making decisions (avoids SSR/client hydration mismatch). Admin role bypasses all permission checks.

## Key Config Values

`server/manifest/config/config.yaml` contains real database credentials and JWT secret. The default MySQL password is `root`. The JWT default secret is `hinay-admin-please-change-me`. Do not commit changes to these values inadvertently.

## Static File Serving

`server/internal/cmd/cmd.go` line 56 maps `/upload` URL path to `resource/upload` directory. These are served **outside** the API middleware group (no auth required). The frontend dev proxy also proxies `/upload` to `:8000/upload`.
