# AGENTS.md

通用后台管理系统脚手架（RBAC admin scaffold），前后端分离：Go 后端 + Nuxt 前端。
另见 `README.md`（功能全览、代码生成器用法）。

## Commands

```bash
# Backend (Go, module name is hinay.cn/admin — not the dir name hinay-admin)
cd server
make run            # go run main.go (dev, :8000)
make vet            # go vet ./...
make fmt            # gofmt -s -w .
make tidy           # go mod tidy
make initdb         # create DB + run manifest/sql/init.sql (mysql client required)
make gen-crud TABLE=biz_xxx TITLE="xx管理"   # CRUD codegen (DRY=1 = dry run)
make gen-api-sql [PKG=flow] [OUT=x.sql]  # scan api/ g.Meta routes -> sys_api seed SQL (CHECK=1 = lint)

# Frontend (Nuxt 4 + Vue 3 + Element Plus + Pinia, yarn)
cd web_src
yarn dev            # dev server on :3000, proxies /api and /upload -> :8000
yarn build          # production build -> .output/

# Docker (requires .env with MYSQL_ROOT_PASSWORD + JWT_SECRET; see .env.example)
docker compose up -d
```

There are **no automated tests**. Verify with `make vet` / `yarn build`.
`gf gen dao|ctrl|service` code generation requires the `gf` CLI and a configured database.

## Architecture

- Layering: `api` (contracts, `g.Meta` routes) → `controller` (thin, generated) → `service` (interface + manual DI) → `logic` (implementation) → `dao`.
- Controllers are single-line pass-throughs generated by `gf gen ctrl` — regenerate instead of hand-editing.
- Service pattern: `service/<mod>.go` defines `IXxx` + `RegisterXxx()`; `logic/<mod>/<mod>.go` implements `sXxx` and self-registers in `init()`.
- Middleware chain in `server/internal/cmd/cmd.go`: CORS → RequestId → RateLimit → SecurityHeaders → OperationLog → AccessLog → HandlerResponse → Auth → Casbin → Controller. `publicPaths` (login, public-key) bypass auth; session endpoints are on `authWhitelist` (authenticated but no RBAC).
- Login passwords are RSA-encrypted (one-time keypair from `/auth/public-key`; private key kept in Redis with 120s TTL, single-use via atomic GETDEL) before bcrypt. JWT logout via Redis blacklist.
- TOTP 2FA (`logic/twofactor`, table `sys_user_totp`): optional per-user. When on, `/auth/login` returns `need2fa + ticket` instead of a token; `POST /auth/login/totp` (public) trades ticket+code for the token (ticket 5min TTL, 5 failed-code limit, replay blocked via `last_step`). Self-service bind/unbind on `/auth/totp/*` (authWhitelist); demo mode blocks bind/unbind. The table intentionally has NO `create_id`/`update_id` → **not** in `ormfill.fillTables`.
- Casbin: `Enforce()` takes the **user ID**; `g`/`p` rows are keyed by 用户ID/角色ID (numeric strings) — role `code` is display-only, renames never break policies. `g(r.sub, p.sub)` maps users→roles. Two policy dimensions: `p, roleId, menu:<id>, *` and `p, roleId, /api/path, METHOD`. The enforcer uses a custom `memAdapter` reading the `casbin_rule` table (not file-based); after policy changes call `casbinx.Reload(ctx)` to rebuild it.
- OperationLog middleware: after the handler returns, an async goroutine (`context.Background()`) inserts audit rows for POST/PUT/DELETE. Multipart uploads never write the raw body to DB — upload logic stashes a file summary (name/size/content-type) via `contextx.SetAuditUpload`, which the middleware reads into the `detail` column.
- AccessLog middleware (`middleware.AccessLog`, registered next to OperationLog outside `ghttp.MiddlewareHandlerResponse`): full-method access journal to `sys_access_log` (GET included), one async row per request with RequestId/user/method/path/query/status/business-code/duration; rows at/over `accessLog.slowMs` (default 1000ms) get `slow=1` + a Warning log; SSE `/api/v1/message/events` is skipped (long-lived stream would fake a multi-minute "slow" request); business-code parsing capped at 64KB response bodies (binary exports skipped); cleanup handler `job.cleanAccessLog` (default 30 days).
- Demo mode (`utility/demox`): `DEMO_MODE` env var takes precedence over `demo.enable` config; when on, password change/reset is globally blocked (428).
- Business-approval features (leave/expense/contract… any approval with its own business table) follow the standard template in `docs/flow-template.md`: 业务与流程分离 — business CRUD on the draft row, submit via the shared `<FlowSubmitDialog :show-form="false">` dialog, `flow_status` written only by `flow.RegisterBizListener` callbacks. Reference implementation: `server/internal/logic/leave` + `web_src/app/pages/biz/leave` + seed `p016`.
- AI chat (`logic/ai`, eino react agent + `eino-ext` openai ChatModel): tool **definitions** live in `logic/ai/tools/` (one file per tool, typed fn + `utils.InferTool`, registered in `tools.Set()`); runtime concerns (SSE tool-step events, timeout, error→result backfill, step persistence) stay in `ai/decorate.go` (`stepTool` wraps every tool). Business-data tools MUST apply `service.DataScope()` with the same filters as the corresponding admin page. Token usage is collected via the model-node streaming callback (goroutine drain — handlers dispatch synchronously, blocking would deadlock the stream).
- **Multi-tenant (docs/multi-tenant.md, switch `multiTenant.enable` in config.yaml, default OFF = legacy single-tenant behavior; OFF still hard-injects platform tenant `tenant_id=1`, i.e. "off = everything scoped to platform tenant" — leftover non-platform rows stay invisible/unloginable, cross-tenant duplicate usernames can't mis-match; clean tenants up before switching back off)**: shared-schema row-level isolation via `tenant_id`, injected at the **driver layer** (`ormfill/tenantorm.go` overrides `DoQuery/DoInsert/DoUpdate/DoDelete/DoExec` on the same `ormfill.Driver` as audit-fill). SELECT is a conservative rewrite (whitelist tables + first-keyword gate + literal masking + top-level-only occurrences + fail-close on UNION/subquery/derived-table/A-join-A/WITH/`;`/placeholder-order anomalies — pure-function tests in `tenantorm_test.go`). INSERT overwrites `tenant_id` from ctx unconditionally; UPDATE/DELETE append `AND tenant_id=?` (gdb passes the condition with a **leading space** — never TrimSpace it). `DoExec` fail-closes raw DML referencing isolated tables **unless marked as coming from the structured DoInsert/DoUpdate/DoDelete funnel** (`withStructuredExec` ctx marker — gdb internally funnels all ORM writes into DoExec). Tenant ctx: `contextx.WithTenant/Tenant/TenantId/WithoutTenant/ScopedToDataTenant` (`consts.CtxTenantKey`, `TenantInfo{Inject}` — platform admin unswitched = Inject:false; X-Tenant-Id header = platform-admin-only ops-switch). Tables: 23 A-class isolated tables in `tenantTables` (incl. `cms_category`/`cms_article`, `sys_access_log`) (same registration style as `fillTables`); `sys_tenant`/`sys_tenant_menu` are NOT injected (platform-guarded table / explicit tenant_id rows). Tenant packages (`sys_tenant_package`, menu-ids JSON snapshot of the grant set, platform table, in `fillTables`): create-wizard prefill via `TenantCreateReq.PackageId` + explicit sync `POST /system/tenant-packages/{id}/sync` reusing the same `applyMenuSet` path as `SetMenus` (rewrite + casbin 双向联动); package page menu 9360 is platform-exclusive (`consts.MenuTenantPackage`). Casbin is domain-model (`sub,dom,obj,act`; p rows: v3=domain, g rows: v2=domain; `casbinx` derives domain from tenant ctx). Admin split: `contextx.IsPlatformAdmin` (role id=1) / `IsTenantAdmin` (code=tenant_admin) / `IsManagerAdmin` (either); tenant admin = "fenced admin" (own-tenant data only, bindable menus/APIs ⊆ `sys_tenant_menu` auth set, never platform surfaces). Config reads MUST go through `internal/logic/configx` (`Value/PlatformValue/PlatformPrefix`) — tenant override order (whitelist keys: sys.name/logo/copyright/allow_register/password.*) on platform-view reads; direct `dao.SysConfig` queries under tenant ctx will "lose" platform rows. Storage keys are tenant-prefixed (`tenant/{tid}/…`, platform keeps legacy layout). Jobs build tenant ctx from `sys_job.tenant_id` (skip+log when tenant disabled/expired); platform sweeping jobs (log clean/flow timeout) use `job.SweepTenants`. `X-Tenant-Id` on requests is ignored+audited for non-platform users.
- File storage (`internal/storage`): `Storage` interface with `local` (disk under `resource/upload`, default) and `s3` (AWS SDK v2 — one client covers MinIO/AWS S3/OSS/COS) impls. Type & connection params live in `sys_config` keys `file.storage.*` (managed on the 全局配置 page); `storage.Current(ctx)` caches the client by config fingerprint, edits take effect without restart (except the `/upload` route, see Gotchas). S3 mode defaults to presigned upload/download: `POST /system/files/presign` issues a presigned PUT (Content-Type is signed), `POST /system/files/presign/confirm` HeadObject-verifies then inserts the row; `sys_file.url` stores the durable ref (`/upload/…` or `s3://bucket/key`), presigned GET URLs are generated on the fly in `List`. Frontend `useFileApi().upload` presigns first and falls back to the relay endpoint. Which storage a row lives on is derived from its `url` prefix — never assume current config for old rows (`storage.ForURL`). Avatar upload (`/auth/avatar`) goes through the same abstraction: `sys_user.avatar` stores the durable ref, and every outbound assembly point (login/userinfo/user list & detail) rewrites it via `storage.ViewURL(ctx, ref)`.
- **XSS sanitize (`utility/sanitizer`, bluemonday)**: every HTML-bearing or free-text field persisted via CMS MUST pass through it in the logic layer before writing — `sanitizer.RichText` for rich-text content (UGCPolicy-based whitelist extended for wangeditor output: inline `style` **property-name** whitelist that deliberately excludes url-bearing properties like `background-image`, `data-ref` kept for media-ref normalization, `class` only `language-*` on `code`), `sanitizer.PlainText` (strip-all) for title/summary/tags/cover/category name/remark. URL-ish attributes (`href`/`src`/`poster`) stay constrained to http/https/mailto+relative by UGCPolicy, so `s3://` srcs get stripped — that's why article content is sanitized **before** `normalizeContentImgs`, which rebuilds `src` from the trusted `data-ref` (including a no-src append branch). Policies are package-level singletons; tests in `sanitizer_test.go` / `cms/article_test.go`.

## Database rules

- Never `g.DB().Model("xxx")` with hardcoded table names — always `dao.Xxx.Ctx(ctx)`.
- `internal/dao/` and `internal/model/{entity,do}/` are generated; do not hand-edit.
- All core tables use soft delete (`deleted_at`), handled by DAO automatically.
- `create_id`/`update_id` are auto-filled by the `ormfill` mysql driver override (`internal/logic/ormfill/`) — business code must never set them. **New business tables must be added to the `fillTables` whitelist** there, and only tables that actually have both columns (otherwise inserts fail with unknown-column errors).
- Audit-fill excluded tables: `casbin_rule`, log tables (`sys_audit_log`, `sys_login_log`, `sys_job_log`, `sys_access_log`), `biz_message_read`, `biz_message_target`.
- **Multi-tenant table rules**: A-class isolated tables (20, see `ormfill/tenantTables`) must carry a `tenant_id` column and be registered there; new tenant tables also register in `fillTables` if they carry audit columns. Unique keys must be tenant-scoped (`(tenant_id, col)`); `ai_conversation.uk_session_id` stays global (session id globally unique). `sys_tenant_menu` (pure relation, no audit cols) is in neither whitelist — explicit tenant_id rows written under platform ctx.
- **Multi-tenant hard rules** (`make tenant-lint` enforces the static ones): no hand-written `tenant_id` conditions in business code (injection owns tenant filtering; platform-row targeting `Where("tenant_id", consts.TenantPlatformId)` allowed only in `configx`/`logic/tenant`); no `.Cache()` on any table; no `tx.Exec`/`.Exec(`/`.Raw(` raw DML on isolated tables (DoExec fail-closes anyway); no FOREIGN KEY constraints; no `tenant_id==x` style branching (tenant differences only via config override / auth set / future module layer); `X-Tenant-Id` stays memory-only (Pinia, never persisted); any new Redis/in-process cache key must carry a tenant dimension or prove the data tenant-free; single timezone everywhere (no UTC mixing).
- Same exception as `sys_user_totp`: AI conversation tables (`ai_conversation`, `ai_chat_message`) have NO `create_id`/`update_id` (owner is `ai_conversation.user_id`) → **not** in `ormfill.fillTables`; conversation delete is physical (`Unscoped`) because `uk_session_id` conflicts with soft-deleted rows.
- Login log has no clear-all by design (GoFrame blocks unconditional DELETE) — per-ID delete only.

## Context & user extraction

Dual-write context (request ctx-var + `context.WithValue`) because logic may run in background goroutines. Always extract the user via `utility/contextx`:

```go
user := contextx.LoginUser(ctx)   // *model.LoginUser or nil
uid  := contextx.UserId(ctx)
token := contextx.JwtToken(ctx)
isAdmin := contextx.IsAdmin(ctx)  // "admin" role check via Casbin
```

## Frontend conventions

- All API calls go through `web_src/app/composables/useRequest.ts` — it implements a concurrent-safe 401 refresh queue (first 401 triggers refresh; others queue and retry; failure drains queue → `/login`).
- Button-level permissions use the `v-permission` directive (`app/plugins/permission.ts`); it waits for `menusLoaded` to avoid SSR hydration mismatch. Admin role bypasses checks.
- Token persists in a cookie (`hinay_token`, readable during SSR so hard reloads don't flash to `/login`); stores in `app/stores/` (user, tags, config).
- Site name/logo/footer come from `sys_config` via the config store — don't hardcode.
- 布局设置 (暗黑模式/主题色/固定头部/Logo/标签栏/水印) 在 `app/stores/settings.ts`, 持久化 localStorage `hinay_layout_setting`; 副作用 (html 的 dark 类、`--el-color-primary-*` 变量) 只在 store action 内应用 — 改设置必须走 `update/toggleDark/setTheme`, 不要直接写 state。`nuxt.config` 的防闪白内联脚本读同一个键。**页面/组件颜色一律用 Element Plus CSS 变量** (`var(--el-bg-color)`、`var(--el-text-color-primary)` 等), 硬编码 hex 会导致暗黑模式失效。
- 水合纪律 (防 "Hydration completed but contains mismatches", 生产才易复现: 服务端时区/ICU 与浏览器不同、生产用户有个性化设置): ① 模板不直接渲染 `new Date()` 等随环境变化的值, 改 onMounted 后生成; ② 会话 (菜单/用户信息, `middleware/auth.global.ts`) 与布局设置 (`plugins/settings.client.ts`) 的恢复都推迟到水合完成后 (`app:suspense:resolve`) — 客户端首次导航先于 mount 执行, 水合前写 store 必然与 SSR 的默认态 HTML 不一致; 水合前只允许 DOM 副作用 (dark 类/主题色变量, 不参与 vnode 比对)。
- File uploads use the shared `FileUploader` component (`app/components/FileUploader.vue`): it wraps el-upload as a mere picker and calls `useFileApi().upload` (presign-first, server fallback). Custom channels (avatar → `/auth/avatar`) use the `uploadFn` prop; error toasts come from `useRequest`, the component stays silent.

## Gotchas

- `server/manifest/config/config.yaml` contains real DB credentials and JWT secret (defaults: mysql `root`, secret `hinay-admin-please-change-me`). Don't commit credential changes inadvertently; `config.docker.yaml` is the container variant.
- `/upload` static files are served **outside** the auth middleware group — public by design, and the route is only registered when `file.storage.type=local` (checked once at startup; toggling storage type requires a restart). In s3 mode file access goes through presigned URLs straight to the object store.
- `make gen-crud` parses DDL from `manifest/sql/init.sql` (no DB connection needed) and auto-wires `logic.go`, `cmd.go`, `useApi/index.ts`; web-based codegen (`gencode.enable`, default off) can zip-download or write into the source tree (refused inside containers).
- SQL layout: `manifest/sql/init.sql` is the single full baseline (base + flow/AI/wechat/leave modules, idempotent, fresh-install only — no legacy migration scripts are kept); `manifest/sql/demo/` holds optional demo seeds (flow test accounts `p012`, leave demo `p016`); `manifest/sql/gen/` is where CRUD codegen writes its output. Flow docs: `docs/flow-integration.md`, `docs/flow-frontend.md`, `docs/flow-template.md`.
- Comments and docs are in Chinese; commit messages follow the existing Chinese `主题: 描述` style.
